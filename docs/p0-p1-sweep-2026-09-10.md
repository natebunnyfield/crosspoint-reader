# P0/P1 sweep, 2026-09-10

Two read-only passes over `lib/` and `src/activities/` + `src/util/`, plus a
third over `src/network/`, `lib/GfxRenderer/` and `src/TextAntiAliasing.cpp`.
Baseline commit `8938fe8ce`. Reproductions used ASan, UBSan and a mutation
fuzzer; the agents could not write to the repo, so every fix below was applied
afterwards.

**Why this file exists.** The standing rule: a sweep must record what it checked
and found CLEAN, or the next pass starts from zero and re-reads the same code.
The CLEAN list is the larger half of what follows and it is the half that
compounds.

## Retracted

**B-054's original mechanism was wrong.** The claim was that SdFat's `getName`
leaves the caller's buffer untouched on failure. It does not: `FsFile::getName`
does `*name = 0` unconditionally on entry, byte-identical in both build
environments, and every variant clears on its own failure path
(`FatName.cpp:94, 163, 220`; `ExFatName.cpp:97, 153`). Do not re-derive that
theory. B-059 is the current leading candidate for the reported symptom.

## CLEAN — checked and found sound

Recording these so they are not re-read.

### Fonts and `.cpfont`
Fuzzed, not merely read: **~52,500 mutated files** (single/multi-byte flips,
truncation, 0xFF runs) across both the BMP-16 and full/astral interval paths,
under ASan+UBSan, with only B-066 found. Interval validation (ordering, overlap,
span, offset continuity, `glyphCount` bound) is thorough. `glyphGeometryFitsData`
(B-045) is enforced at **both** load sites. The overflow LRU commits only after
all I/O succeeds and keeps its bitmap out-of-band, and `GfxRenderer` correctly
routes overflow glyphs around the `bitmap[dataOffset]` arithmetic.
`mergeIntoAdvanceTable` cannot overrun `mergedCap`; a dropped advance-table
entry falls back to `getGlyph()->advanceX`, so the cap is not a measure/draw
hole.

### HAL
`getName`'s empty-on-failure behaviour is correct and covers both
`SdCardFontRegistry` callers. Every other `HalFile` method is a thin locked
pass-through; the same invisible-failure shape was looked for specifically and
not found. `HalClock`, `HalDisplay`, `HalSystem`, `Logging` (ring buffer, magic
word, `logPrintf`'s clamp), `BuildScratch`, `LigatureControl`,
`MissingGlyphLedger`, `EpdFontFamily::getFont`'s fallback order, `Utf8`
(continuation validation, overlong/surrogate/range rejects), `LiangHyphenation`
— all sound. `PersistableStore`'s temp-file write/recover protocol is the
pattern B-067 was missing.

### EPUB cache deserializers
`Page::deserialize` (caps, nothrow, null checks), `TextBlock::deserialize` (word
cap, geometry reject, full offset validation, no `arenaSize` overflow),
`TextBlock::render`'s focus split (triple-clamped — checked specifically because
deserialize does *not* validate `focusBoundary`), `rubyserial::read`,
`ImageBlock::deserialize`, `CssParser::loadFromCache`, and all six of
`Section`'s on-disk LUT readers. `Section::loadPageAt` does not bounds-check
`lutOffset`, but every deserializer downstream is bounded, so a crafted `.bin`
yields a nonsense page rather than an OOB access.

### Decompression, images, parsers
`itemName[256]` in all four central-directory scanners; the EOCD scan and its
unaligned-load fix; `readFileToMemory`'s 16 MB cap; `InflateStream`'s
one-shot/ring invariants and no-progress guard. PNG: B-023's guard present, all
five colour types × both depth classes stay inside `rawRowBytes`, PLTE clamped,
all four unfilters bounded. JPEG: the MCU clamp is not latent. XTC 2-bit plane
indexing guarded on **both** cover and thumbnail paths.
`StreamingJsonParser`, `ReleaseJsonParser`, `MiniBidi`, `FsHelpers`,
`XmlEncodingTables` (all 30 tables verified at exactly 128 entries),
`htmlEntities` (all 252 keys verified ascending), and every expat `atts[i+1]`
walk.

### Activities
No bare `new` in the swept directories. No `resize`/`reserve` sized from file or
network content outside the fixed sites. Every fixed buffer measured against its
worst input; translated format specifiers match across both YAMLs. Divide and
modulo guarded at every site. Stale-index audit across six activities — all
clamped or state-gated. `OptionPopup::show` copies into `ownedStrings`, so stack
locals do not dangle. `settingrow::activate` captures by value deliberately.
`FontUpdater`'s stage-then-commit ledger is correct on the cancel path.

### Disproved before reporting
Would have been wrong, and each was dropped: `utf8SafeTruncateBuffer`'s
`char saved[4]`; `flushPendingLines`' unchecked `pendingLines_[0]/[1]`;
`Epub::resolveHrefToSpineIndex`'s reference-into-temporary;
`EpdFont::getKerning`'s mini-matrix indexing; the advance-cache tail drop; and
expat's negative-length path (B-069 — unsafe in appearance, safe in fact).

## Corrections to the sweep's own claims

- **The loop task stack is 16 KB**, not 8 KB — `SET_LOOP_TASK_STACK_SIZE(16 * 1024)`
  at `src/main.cpp:781`. The 8 KB figure is the RENDER task. Three sub-threshold
  stack items were downgraded on that basis; **nothing in either sweep is a
  stack-overflow finding.**
- `BUGS.md`'s B-024 entry cites `XtcParser` as *"the pattern to copy"*. The clamp
  there is sound; the `reserve` it fed was not (B-065).

## Known and NOT fixed

- **B-070's residual.** The page LUT now reserves 96 entries early, which takes
  the allocation while the heap is healthiest and covers an ordinary chapter. A
  longer chapter still grows, and that growth still throws. The `make_shared`
  calls on the same path (~120 B and ~40 B, once per line) are small enough to
  fail only near exhaustion and were left alone.
- **`ClearCacheActivity`**: dismissing the confirm popup with Back leaves the
  destructive screen armed, so the next Confirm clears every cache including
  `progress.bin`. Every other popup in that tree treats dismissal as
  cancel-and-leave. Not changed — it is a deliberate-looking UI choice and
  changing it is the owner's call.
- **`ProgressFile::writeAtomic`** returns on a short write without unlinking its
  `.tmp`, leaving a stray file. Cosmetic.
- **`removeCredential`'s** discarded return: the in-memory erase happens first
  and the list is re-derived, so only an SD write failure survives the session.
